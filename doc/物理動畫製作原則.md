# JHphysics 物理動畫製作原則

本文件供 Luna 或其他協作者製作、改寫教學動畫時使用。目標是讓學生**看見指定的物理現象**，而不是把題目、公式和答案重新排成一個網頁。每一題先定義用途，再決定圖像、運動、向量和控制項；不得把所有題目套入同一個版型與功能清單。

**給製作 AI 的分段指令：第一階段僅輸出規格表並主動停止，待收到「確認規格」指令後，才允許生成 Canvas 繪圖與 JavaScript 邏輯碼。** 規格表若仍有未決定的物理意義、可調參數或畫面內容，先提出問題，不得用自行猜測的版本開始寫程式。使用者已在同一委託明確確認規格或直接授權跳過此階段時，依其指示執行。

參考案例：`book1/Chapter3/example1.html`～`example8.html` 與共用的 `chapter3.js`、`chapter3.css`；`book2/Chapter3` 四個碰撞動畫；`book1/Chapter3/ex7.html`；`doc/復古風格.md`。其中 `ex7.html` 的復古視覺和簡潔控制可作風格參考，但其固定 `800 × 450` 畫布與 `780px` 控制列不可直接當作手機版規範。手機版另依 [動畫手機版面與繪圖效能原則](動畫手機版面與繪圖效能原則.md) 驗收。

## 1. 開工前先確認用途

若委託只給題目、講義圖片或「做成動畫」，先提出**與製作決策直接相關**的少數問題，收到答案後才定稿。優先確認：

1. 這頁要學生觀察甚麼？例如「推力改變時，木塊是否相對斜面滑動」，而非「展示牛頓第二定律」。
2. 這是忠於原題的演示、定性比較，還是允許任意參數的模擬？原題數值、條件與示意圖哪些必須固定？
3. 哪些物件要動、誰相對誰動、要看見哪些關鍵時刻？是否需要循環、慢放、暫停或重播？
4. 要顯示哪些物理量或向量？要附在物體上、另開受力圖，還是完全不顯示？
5. 哪個參數改變後會產生值得觀察的差異？可調範圍、預設值與是否允許離開原題條件？
6. 頁面是否需要公式、答案、解說文字或說明視窗？**未明確要求時，預設不加入。**
7. 目標裝置與瀏覽方式是甚麼？手機橫向及內建瀏覽器是本專案的基本驗收環境。

使用者已在委託中回答的事項不再重問。若不確定會改變物理意義、圖像或操作方式，明列假設請使用者選擇；不要自行發明教學目的。風格喜好可以依既有範例推斷，物理語意不能。

## 2. 先交一頁「動畫規格」，再寫程式

每題先列以下內容，作為實作與驗收的共同依據：

| 欄位 | 必須說清楚的事 |
| --- | --- |
| 觀察目標 | 學生看完應能直接指出的現象或差異，限 1～2 項 |
| 來源 | 對應講義圖片、題號、已確認條件；與原圖不同之處 |
| 場景 | 物件、形狀、位置、約束、座標軸及參考系 |
| 時序 | 初態、動作、關鍵事件、終態；循環或停止條件 |
| 物理量 | 要顯示的力、速度、加速度、位移等，以及各自所屬物件 |
| 控制 | 播放、暫停、重置及真正有教學價值的可調參數 |
| 不顯示 | 依委託排除的公式、答案、提示、圖表、額外向量等 |
| 驗收 | 換參數後可見的結果、物理關係及手機畫面檢查 |

講義圖片是題意與幾何關係的依據；先逐物件、逐箭頭讀圖，不把參考圖片只當縮圖或配色素材。若圖片與文字互相矛盾，先指出矛盾。圖中的箭頭、角度、接觸點與連線若會影響物理意義，必須重現或經使用者同意後簡化。

規格確認後才進入實作。若後續發現規格中的物理條件不可能同時成立，或改動會改變教學目的，先更新規格並請使用者確認；純粹的程式修錯、版面修正與已確認範圍內的實作細節可直接完成。

## 3. 先畫對，再讓它動

- **靜態機構圖是第一道交付門檻。** 規格確認後，先做初始畫面並與原題圖片並排核對，通過後才加入動畫。核對的是機構的拓撲與物理連接：有幾個滑輪、繩子如何繞過、在哪裡轉向、物體掛在哪裡、哪裡接觸或固定、力作用於誰。不能只因物件名稱與顏色相同就視為重現原圖。
- 逐條追蹤繩、桿、軌道、彈簧與受力箭頭的起點、終點和中途接點。連續的繩不得憑空斷開或在沒有滑輪、環或接觸點的地方突然轉向；遮在物體背後的線段也要符合完整路徑。若使用者只給小圖，看不清楚的關鍵連接須先詢問，不能補出不存在的機構。
- 場景只放解釋該現象所需的物件。物體、支架、地面、繩、彈簧、滑輪、碰撞點等應有清楚的接觸與連接關係；不得浮空、穿模、越過邊界或在重置後跳位。
- 物體的運動必須服從題目約束。例如繩長不變、相接物體不分離、斜面上的物體沿斜面移動，或題目要求時相對斜面靜止。不要用互不相關的 `sin()` 或循環平移替代所需的因果過程。
- 每個運動量明確指定參考系。畫面捲動或攝影機跟隨時，不能讓學生誤認物體停止、反向或加速；必要時保留固定地面、座標或相對位置參照。
- 在預設值和可調範圍兩端都檢查初態、轉折與終態。運動方向、速度變化、碰撞前後和停止條件要與所選物理模型一致。

**向量是物理量，不是裝飾箭頭。** 每支箭頭都要知道「屬於哪個物體、代表甚麼量、在哪個參考系、方向和長度如何決定」。力、速度、加速度、動量不能混用；向量要從所作用的物體或明確的受力圖位置出發，隨物體或狀態正確更新。若箭頭長度表達大小，同類量要用一致比例並提供圖例或標值；若僅表示方向，明示「方向示意」。顏色只作輔助辨識，不可代替標籤與物理定義。分力、合力、正向力、繩張力及假想力都須符合題目的座標系與條件；不因共用模板而自動加入。

### 以可移動斜面題為例

`book1/Chapter3/example7.html` 的規格應先回答：水平推力改變時，要看的是斜面與木塊一起移動、木塊相對斜面滑動，還是只看某一特定推力下的平衡？若要比較推力，推力控制必須真正改變兩者的相對運動。`book1/Chapter3/ex7.html` 已有「推力 F」控制和相對位移狀態，方向較接近這個觀察目標；但仍要依原題檢查向量與幾何，並補手機版配置。不能只把相同場景套上通用倍速按鈕。

### 以阿特伍機題為例

`book1/Chapter3/阿特午ex4.png` 中，兩端繩子從**同一個定滑輪的左右兩側切線直接垂下**，繩子與滑輪上半圓相切，A、B 分別掛在兩段垂直繩的末端。`example4.html` 目前畫出的卻是：繩子從滑輪左右側的中心高度水平伸到遠處，再在沒有其他滑輪的位置折成直角垂下；A、B 也因此離滑輪過遠。這不是示意圖的簡化，而是把裝置改成了另一個不存在的機構。應先修正繩與滑輪的幾何，對照初始畫面確認後，才檢查 A、B 等量反向位移、支點支持力與張力。播放時亦不能只因為需要循環就讓原本下落的物體自行反向上升。

## 4. 控制項只為可觀察的差異服務

- 先有可驗證的現象差異，才加入參數。若改變一個數值不會讓學生看見有意義的差異，就固定它。優先選少量、直觀、在題目允許範圍內的整數或離散選項。
- 每個控制都要寫明「改它會改變甚麼」。修改參數後要重建相關初態、運動與畫面；標示值、幾何和物理計算須同步更新。不得只有標籤變動，動畫仍沿用舊值。
- 預設值要能清楚展示主現象；至少再選一個對照值，讓方向、幅度、相對運動或最終狀態出現可辨識差異。避免整段播放看起來一樣。
- 播放／暫停／重置須有一致行為。重置回到目前參數的初態，清除上一輪軌跡與事件狀態；參數重設為預設值與否由規格明訂。
- 倍速、跳階段、圖表、質心、軌跡、說明按鈕都屬**按題選用**功能。除非觀察目標需要，不能因風格文件或共用元件存在就全部塞進頁面。
- 可調值的整個範圍都要有有效的物理狀態。實作須處理本題可能碰到的邊界：例如推力不足以克服靜摩擦時保持靜止、分母為零或接近零時限制輸入或切換模型、碰撞物體重疊時校正位置並避免重複施加衝量。不得讓 `NaN`、無限值或越界座標進入動畫狀態；超出模型適用範圍的選項應移除或明確限制。

## 5. 畫面以現象為主

預設交付為「清楚的場景＋必要的控制」。畫面首先讓學生看見物件、相對位置及運動的變化；觀看者不讀文字也應能辨認主要現象。題目敘述、公式推導、答案卡、操作提示、即時數值、圖表與大段文字，只有使用者要求或觀察目標必需時才顯示。需要保留的補充內容可放在可開啟的說明區，不佔據主要動畫空間。**不要以解說文字掩蓋畫面本身未呈現的現象。**

預設採取以下減法規則：

- 不放會持續跳動但不影響判讀的時間、座標、速度、能量等數字。需要比較大小時，先考慮位置、距離、長度或運動差異；精確數值只有確有教學用途才顯示。
- 不預設疊滿力、速度、加速度、動量、分力與軌跡。每題只保留達成觀察目標所需的向量；其餘可由使用者指定是否提供切換檢視。
- 不為「看起來完整」增加儀表板、卡片、圖例、漸層、陰影、粒子效果或多色標記。視覺效果若會搶走對運動與因果的注意力，就刪除。
- 用少量顏色區分必要物件或狀態，保持足夠對比。每個標籤都須能回答「拿掉後會不會誤解？」；不會就拿掉。
- 控制項以能產生可見差異的選項為限。空白與簡潔是正常的教學設計結果，不需要用資訊填滿畫面。

驗收時先看預設畫面三秒：能否指出「誰在動、怎樣動、改參數後差在哪裡」？若必須先讀旁邊一整欄公式和答案才看得懂，應重做場景或運動，而非再加說明。

`book1/Chapter3` 多數 `example*.html` 頁面共用「副標題、公式、答案、提示、倍速」版型；`example4.html` 已移除公式與答案側欄，但仍保留通用倍速控制。這類控制應由各題觀察目標決定：有值得比較的物理參數才加入，沒有時可能只需播放、暫停與重置。`book2/Chapter3` 的碰撞頁面有依題目選的質量比例、碰撞模式或視角等控制，可作「控制項與現象對應」的參考；不是要求照搬其外觀或每個功能。

風格須從題目讀圖清晰度出發。`doc/復古風格.md` 和 `ex7.html` 的紙色、線條、排版可以選用；該文件中的 4:3、所有向量、質心、能量圖等要求，若與本題用途或使用者明示的精簡需求衝突，以本文件的逐題規格為準。風格不能改變物理量的意義，也不能犧牲手機可用性。

## 6. 系統行為與底層邏輯

### 集中管理狀態

所有**會變動**的物理參數、模擬時間、物體位置與速度、階段、播放狀態及控制項目前值，集中存放在單一 `state` 物件。DOM 節點、固定的繪圖尺寸與不變的常數可另行保存；畫面顯示的衍生數值應由 `state` 計算，不能另存一份而逐漸與模擬脫節。避免場景函式各有互不相通的全域變數，或把本應受控制項影響的運動寫死在繪圖函式裡。

控制項變更統一走一個狀態更新入口：先驗證輸入，再更新參數，重建對應初態，清除舊軌跡、碰撞旗標及上一輪時間，最後重繪。播放、暫停、重置也應經過明確的狀態轉換；重置不得只把畫面清空，卻留下舊速度或計時器。不要在每一幀由 DOM 反覆讀取參數。

### 模擬時間與渲染分離

`requestAnimationFrame` 只決定何時**顯示**下一幀，不能把「每呼叫一次就移動固定距離」當成物理時間。若是數值積分、碰撞或彈簧系統，使用固定邏輯時間步長更新狀態，渲染則讀取已算好的狀態；必要時插值。用累積器接收實際經過時間，並限制單次追趕步數，避免手機從背景返回後一次計算過多步。

若運動可由正確的解析式直接依模擬時間求出位置，例如已知初速與固定加速度，則可用經過時間計算，不必為了形式而增加固定步長迴圈。兩種方法都必須讓同一參數與同一**模擬時間**得到相同的物理狀態；手機掉幀可以減少顯示的畫面，不能讓物體因此走得較慢或改變軌跡。不可用隨意的正弦往返或畫面循環代替題目所要求的加速度、碰撞或停止過程。

## 7. 實作與驗收門檻

1. **物理核對**：用原題條件核對方向、受力對象、約束與關鍵數值；在每個可調參數的代表值重算結果。定性動畫也必須保持方向和因果正確。
2. **原圖與靜態畫面核對**：將原題圖片和動畫初始畫面並排，逐一確認物件數量、相對位置、連線、接觸、繩路徑、轉向點和箭頭歸屬。機構圖不對即不進入動畫驗收。
3. **逐幀核對**：檢查初態、運動中、關鍵事件與終態的截圖或錄影。物體及向量不穿透、不錯位、不遮住關鍵現象；不同參數確有可見差異。
4. **操作核對**：播放、暫停、重置、改參數後再播放均正確；切換頁面或背景時不產生重複動畫循環。
5. **手機核對**：橫向、內建瀏覽器工具列佔空間時，場景等比例、控制可用、關鍵物件可見；依手機版面文件檢查清晰度和效能。
6. **需求核對**：逐條比對動畫規格的「觀察目標」與「不顯示」。觀察目標要由畫面和互動本身達成；不得用額外公式或文字宣稱已達成。
7. **邊界核對**：用參數最小值、預設值、最大值，以及零速度、臨界摩擦或剛接觸等本題相關狀態測試；不得出現 `NaN`、無限值、穿模或失控的動畫循環。

交付時附上每題的短規格、來源、預設值／對照值、實際驗收結果與尚未實測的裝置。未確認的物理假設或未完成的實機測試必須明列，不能寫成已驗證。
